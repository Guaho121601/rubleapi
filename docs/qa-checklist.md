# rubleapi mvp qa checklist

## 1. build

- [ ] выполнить `npm run build`
- [ ] убедиться, что команда завершилась без ошибок
- [ ] убедиться, что после сборки появился файл `dist/app/server.js`

## 2. server start

- [ ] выполнить `npm start`
- [ ] убедиться, что основной fastify-сервер стартовал без ошибок
- [ ] если порт `3000` занят, найти процесс командой `netstat -ano | findstr :3000`
- [ ] остановить лишний процесс командой `taskkill /pid взять реальный pid из netstat /f`
- [ ] снова выполнить `npm start`

## 3. health endpoint

- [ ] выполнить `curl http://127.0.0.1:3000/health`
- [ ] убедиться, что статус ответа `200`
- [ ] убедиться, что ответ содержит `{"status":"ok","service":"rubleapi"}`

## 4. rates api

- [ ] выполнить `curl http://127.0.0.1:3000/api/rates/latest`
- [ ] убедиться, что сервер отвечает json
- [ ] если данных нет, зафиксировать это как ожидаемую проблему данных, а не падение сервера
- [ ] выполнить `curl "http://127.0.0.1:3000/api/rates/latest?symbols=usd,eur,cny"`
- [ ] убедиться, что сервер отвечает json без 500-ошибки
- [ ] проверить, что в ответе нет валют вне запрошенного списка
- [ ] при наличии данных проверить поля `source`, `date`, `fetchedat`, `base`, `rates`

## 5. widget page

- [ ] открыть `http://127.0.0.1:3000/widget`
- [ ] убедиться, что страница отдается как html
- [ ] убедиться, что видны настройки валют, темы, округления и брендинга
- [ ] убедиться, что при изменении настроек обновляется live-preview
- [ ] убедиться, что при изменении настроек обновляется готовый `script`-код
- [ ] нажать кнопку копирования и убедиться, что код копируется без ошибки
- [ ] убедиться, что при `data-branding="false"` показывается предупреждение про платную версию

## 6. docs page

- [ ] открыть `http://127.0.0.1:3000/docs`
- [ ] убедиться, что страница отдается как html
- [ ] убедиться, что на странице есть разделы:
- [ ] `быстрый старт`
- [ ] `пример script-кода`
- [ ] `параметры виджета`
- [ ] `установка на обычный html-сайт`
- [ ] `установка на tilda`
- [ ] `установка на wordpress`
- [ ] `если виджет не загрузился`
- [ ] ссылка на `/widget`

## 7. landing page

- [ ] открыть `http://127.0.0.1:3000/`
- [ ] убедиться, что страница отдается как html
- [ ] убедиться, что есть первый экран с описанием продукта
- [ ] убедиться, что кнопка `настроить виджет` ведет на `/widget`
- [ ] убедиться, что кнопка `документация` ведет на `/docs`
- [ ] убедиться, что есть блоки `что умеет`, `для кого`, `пример кода`, `api`

## 8. widget.js

- [ ] выполнить `curl http://127.0.0.1:3000/widget.js`
- [ ] убедиться, что файл отдается со статусом `200`
- [ ] убедиться, что ответ содержит javascript, а не html или json
- [ ] убедиться, что `widget.js` читает `data-symbols`
- [ ] убедиться, что `widget.js` читает `data-theme`
- [ ] убедиться, что `widget.js` читает `data-round`
- [ ] убедиться, что `widget.js` читает `data-branding`
- [ ] убедиться, что при ошибке api виджет показывает аккуратное сообщение, а не ломает страницу

## 9. cors

- [ ] открыть `test-widget.html` в браузере или через локальный html-хостинг
- [ ] убедиться, что внешний html может загрузить `http://127.0.0.1:3000/widget.js`
- [ ] убедиться, что запросы виджета к `http://127.0.0.1:3000/api/rates/latest` не блокируются cors
- [ ] открыть devtools и проверить, что нет cors-ошибок в console и network

## 10. database files and gitignore

- [ ] открыть `.gitignore`
- [ ] убедиться, что в `.gitignore` есть `node_modules/`
- [ ] убедиться, что в `.gitignore` есть `dist/`
- [ ] убедиться, что в `.gitignore` есть sqlite/db-артефакты
- [ ] выполнить `git status --short`
- [ ] убедиться, что в статусе нет `node_modules`
- [ ] убедиться, что в статусе нет `dist`
- [ ] убедиться, что в статусе нет `*.sqlite`
- [ ] убедиться, что в статусе нет `*.db`

## 11. manual test scenario

1. выполнить `npm run build`
2. выполнить `npm start`
3. открыть `http://127.0.0.1:3000/`
4. перейти на `/widget`
5. выбрать `usd`, `eur`, `cny`
6. выбрать `light`
7. выбрать округление `2`
8. оставить брендинг `true`
9. скопировать сгенерированный `script`
10. вставить код в `test-widget.html`
11. открыть `test-widget.html` в браузере
12. убедиться, что виджет загрузился и показывает курсы или корректное сообщение об отсутствии данных
13. перейти на `/docs`
14. убедиться, что документация соответствует текущему mvp

## 12. pre-deploy checklist

- [ ] `npm run build` проходит без ошибок
- [ ] `npm start` запускает основной сервер
- [ ] `/health` отвечает `200`
- [ ] `/` отвечает html
- [ ] `/widget` отвечает html
- [ ] `/docs` отвечает html
- [ ] `/widget.js` отвечает javascript
- [ ] `/api/rates/latest` отвечает без 500-ошибки
- [ ] cors не блокирует внешний виджет
- [ ] в git status нет `node_modules`, `dist`, sqlite/db-файлов
- [ ] в проект не добавлены функции вне mvp
- [ ] не добавлены оплата, личный кабинет, криптовалюты, банковские курсы, live forex, react, vue, jquery
